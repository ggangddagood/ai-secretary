# Spec: stocks-brief

## 목표

관심 종목의 종가·등락과 시장 지표를, 크게 움직인 종목의 뉴스 근거와 함께 한국어로 정리해
하루 두 번(미국장 마감 후 / 한국장 마감 후) 텔레그램으로 보낸다.

기존 AI 브리핑(`secretary.main`)과 **완전히 독립된 파이프라인**이다. 실행 시각도, CLI도,
워크플로도 분리되며 `state/seen.json`을 읽지도 쓰지도 않는다.

## 요구 동작

### 실행과 시장 선택

- `python -m secretary.stocks --market us` 는 미국 시장 브리핑을 만들어 발송한다.
- `python -m secretary.stocks --market kr` 는 한국 시장 브리핑을 만들어 발송한다.
- `--market` 은 필수 인자다. 생략하면 argparse가 exit 2로 거부한다 — 기본값을 두지 않는다.
  잘못된 시장으로 조용히 도는 것보다 즉시 실패하는 편이 낫다.
- `--dry-run` 은 발송 없이 렌더링 결과를 stdout에 출력하고 exit 0.
- `--verbose` 는 DEBUG 로깅.

### 시세 조회

- 조회 대상은 **관심 종목**(환경 변수로 주입)과 **시장 지표**(코드 상수) 두 갈래다.
- 시장 지표는 시장별로 고정한다.

  | 시장 | 지표 |
  | --- | --- |
  | `us` | `^GSPC`(S&P 500), `^IXIC`(나스닥), `USDKRW=X`(원달러) |
  | `kr` | `^KS11`(코스피), `^KQ11`(코스닥), `USDKRW=X`(원달러) |

- 조회는 Yahoo Finance v8 chart 엔드포인트를 심볼 하나당 한 번 GET 한다.
  `https://query1.finance.yahoo.com/v8/finance/chart/{심볼}?range=1mo&interval=1d`
  심볼은 URL 인코딩한다(`^`, `=` 포함).
- 등락률은 **`indicators.quote[0].close` 배열에서 `None`을 제거한 유효값의 마지막 두 개**로
  계산한다: `(최신 - 직전) / 직전 * 100`.
- 기준일(`as_of`)은 최신 유효 종가에 대응하는 `timestamp` 를 `meta.exchangeTimezoneName`
  타임존으로 변환한 **날짜**다.

### 급등락 해설

- 관심 종목 중 등락률의 절댓값이 임계값(`STOCKS_MOVE_THRESHOLD`, 기본 `5.0`) 이상인 것을
  급등락 종목으로 본다. 시장 지표는 대상이 아니다.
- 급등락 종목마다 Google News RSS로 헤드라인을 수집한다.
  `https://news.google.com/rss/search?q={검색어}&hl={언어}&gl={국가}&ceid={ceid}`
  검색어는 그 종목의 **표시명**이다. 언어 파라미터는 시장에 따른다:
  `us` → `hl=en-US&gl=US&ceid=US:en`, `kr` → `hl=ko&gl=KR&ceid=KR:ko`.
- 발행 시각이 **최근 3일 이내**인 헤드라인만 쓰고, 종목당 최대 5건까지 쓴다.
- 헤드라인을 확보한 종목들을 **한 번의 LLM 호출**로 묶어 해설을 만든다. 해설은 종목당
  한국어 한 줄이다.
- 발송 메시지에는 해설과 함께 근거 헤드라인의 제목·링크를 싣는다.

### 렌더링과 발송

- 텔레그램 `parse_mode=HTML`. 메시지 한 건은 4096자를 넘지 않으며, 넘으면 블록 경계에서 나눈다.
- 헤더에 시장 이름과 기준일을 표시한다. 기준일이 실행 시각의 그 시장 로컬 날짜와 다르면
  헤더에 **휴장**을 함께 표시한다.
- 발송은 기존 텔레그램 봇과 채팅방(`TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`)을 그대로 쓴다.

## 불변 조건

- **CRITICAL: 헤드라인을 확보하지 못한 종목에 해설을 생성하지 않는다.** 등락률만 싣는다.
  기존 파이프라인의 "본문 없으면 요약 없음"과 같은 규칙이다 — 근거 없는 해설은 환각이다.
- **CRITICAL: 등락률을 `meta.chartPreviousClose` 로 계산하지 않는다.** 이 값은 조회 창
  시작 **이전**의 종가이지 직전 거래일 종가가 아니다. 실측에서 삼성전자의
  `chartPreviousClose`가 239500인데 실제 직전 종가는 268500이었다. 이 값을 쓰면 등락률이
  조용히, 그럴듯한 숫자로 틀린다.
- **CRITICAL: 모든 환경 변수는 `secretary/config.py` 를 통해서만 읽는다.**
- **CRITICAL: 시크릿을 로그·예외 메시지·발송 메시지·커밋에 남기지 않는다.**
- 이 파이프라인은 `state/seen.json` 을 읽지도 쓰지도 않는다. 상태 파일이 없다.
- 관심 종목 목록을 리포지토리에 커밋하지 않는다. 리포지토리가 공개이므로 환경 변수로만 주입한다.
- 기존 `secretary.main` 파이프라인의 동작을 바꾸지 않는다. 공용 모듈 추출은 리팩터링이며
  기존 테스트가 그대로 통과해야 한다.

## 범위 제외

- 실적·배당·공시 일정 알림 (상태 파일이 필요해진다)
- 보유 수량·평가손익·포트폴리오 계산
- 매매 신호, 목표가, 투자 판단 제시
- 장중 실시간 알림 (하루 두 번 배치뿐이다)
- 차트 이미지 생성
- AI 브리핑 파이프라인과의 메시지 통합 (별도 발송이다)
- 종목별 뉴스 **본문** 추출 (헤드라인까지만 쓴다)

## 엣지 케이스

| 상황 | 처리 |
| --- | --- |
| `close` 배열 마지막 원소가 `None` | 제거하고 그 앞의 유효값을 최신 종가로 쓴다. 실측에서 `035720.KQ`가 그랬다 |
| `close` 유효값이 2개 미만 | 그 심볼은 조회 실패로 본다. 등락률을 만들 수 없다 |
| 직전 종가가 `0` | 조회 실패로 본다. 0으로 나누지 않는다 |
| 심볼 하나가 타임아웃·HTTP 에러·`chart.error` | 경고 로그 후 그 심볼만 건너뛴다. 나머지로 진행 |
| 관심 종목·시장 지표 조회가 **전부** 실패 | 실패 알림을 발송하고 exit 1 |
| 관심 종목 목록이 비어 있음 | 경고 로그 후 시장 지표만으로 브리핑을 만든다. 실패가 아니다 |
| 관심 종목 목록 항목의 형식이 잘못됨(빈 문자열 등) | 그 항목만 건너뛴다. 경고 로그 |
| 기준일이 그 시장 로컬 날짜와 다름(공휴일) | 마지막 거래일 종가를 그대로 싣고 헤더에 "휴장"을 표시한다 |
| 환율(`USDKRW=X`)의 기준일 | 24시간 거래라 휴장 판정에서 제외한다. 최신값을 그대로 싣는다 |
| 급등락 종목이 0건 | 해설 절을 통째로 생략한다. 시세만 발송한다 |
| 뉴스 RSS 수집 실패 | 경고 로그 후 그 종목은 해설 없이 간다. 전체를 실패시키지 않는다 |
| 최근 3일 내 헤드라인이 0건 | 그 종목은 해설 없이 등락률만 |
| LLM 호출 실패 | **경고 로그 후 해설 없이 발송한다.** 시세가 본체이고 해설은 부가다 |
| LLM 응답에 일부 종목이 빠짐 | 빠진 종목만 해설 없이 싣는다. 경고 로그 |
| LLM이 헤드라인 없는 종목의 해설을 반환 | 그 해설을 폐기한다. 근거 없는 해설은 싣지 않는다 |
| 텔레그램 발송이 중간 조각에서 실패 | exit 1. 실패 알림도 보내지 않는다(같은 채널이 죽었다) |
| Yahoo가 429로 차단 | 조회 실패 경로를 탄다 — 전부 실패면 실패 알림 + exit 1. 조용히 끝나지 않는다 |

## 외부 인터페이스

### CLI

```
python -m secretary.stocks --market {us|kr} [--dry-run] [--verbose]
```

- exit 0: 발송 성공, 또는 `--dry-run` 정상 종료
- exit 1: 브리핑 생성 실패(실패 알림 발송) 또는 텔레그램 발송 실패
- exit 2: 인자 오류(argparse)

### 환경 변수

| 이름 | 필수 | 기본값 | 역할 |
| --- | --- | --- | --- |
| `TELEGRAM_BOT_TOKEN` | O | — | 기존 봇과 동일 |
| `TELEGRAM_CHAT_ID` | O | — | 기존 채팅방과 동일 |
| `GEMINI_API_KEY` | O | — | 급등락 해설 생성 |
| `STOCKS_WATCHLIST_US` | X | 빈 값 | 미국 관심 종목 |
| `STOCKS_WATCHLIST_KR` | X | 빈 값 | 한국 관심 종목 |
| `STOCKS_MOVE_THRESHOLD` | X | `5.0` | 급등락 판정 기준(%) |
| `HTTP_TIMEOUT` | X | `20` | 외부 HTTP 타임아웃(초) |

`--dry-run` 일 때는 텔레그램 두 개가 필수 검사에서 빠지고 `GEMINI_API_KEY` 만 요구된다
(기존 `secretary.main` 과 같은 규칙).

### 관심 종목 목록 형식

`STOCKS_WATCHLIST_*` 는 쉼표로 구분된 `심볼:표시명` 목록이다.

```
AAPL:애플,NVDA:엔비디아,TSLA:테슬라
005930.KS:삼성전자,035720.KQ:카카오
```

- 표시명을 생략하면(`AAPL`) 심볼을 표시명으로 쓴다.
- 앞뒤 공백은 제거한다. 빈 항목은 건너뛴다.
- 표시명에 콜론이 들어갈 수 있으므로 **첫 콜론에서만** 나눈다.
- 표시명은 급등락 해설의 뉴스 검색어로도 쓰인다.

### Yahoo v8 chart 응답에서 읽는 필드

- `chart.error` — null이 아니면 조회 실패
- `chart.result[0].meta.exchangeTimezoneName` — 기준일 계산용 타임존
- `chart.result[0].meta.currency` — 통화 표기
- `chart.result[0].timestamp[]` — epoch 초
- `chart.result[0].indicators.quote[0].close[]` — 종가. `None` 이 섞인다

## 확정 근거

- **같은 리포지토리 안 별도 파이프라인** — 재사용되는 코드는 전체 1344줄 중 발송·HTTP·로깅
  약 154줄(11%)뿐이고 도메인은 겹치지 않는다. 그럼에도 리포를 나누지 않은 이유는 그 11%가
  봇 토큰 마스킹이라는 가장 조심스러운 코드이기 때문이다. 복제하면 두 곳에서 관리해야 한다.
- **Yahoo v8 chart 직접 호출** — 한국·미국 종목과 지수·환율을 키 없이 한 소스로 커버하는
  유일한 선택지였다. KIS Open API는 계좌 개설과 24시간 토큰 갱신이 붙고, Twelve Data는
  무료 티어의 KRX 포함 여부가 불확실하며, Alpha Vantage 무료는 하루 25요청으로 부족하고,
  pykrx는 미국을 못 준다. 계획 단계에서 6개 심볼을 실제 호출해 전부 HTTP 200을 확인했다.
- **`yfinance` 라이브러리를 쓰지 않는다** — pandas 의존성을 끌어오지 않고, 기존
  `http.make_client` 를 재사용해 STANDARDS의 "외부 HTTP는 `make_client` 를 쓴다"를 지킨다.
  실측에서 기존 User-Agent(`ai-secretary/0.1`)로 6개 심볼이 모두 200을 반환해, 브라우저
  User-Agent 위장이 필요 없음을 확인했다.
- **`range=1mo`** — `5d` 는 설·추석 연휴에 유효 거래일이 2개 미만이 될 수 있다.
  실측에서 `1mo` 는 22~23 거래일을 준다.
- **관심 종목을 GitHub Actions Variables에 둔다** — 이 리포지토리는 공개다. 종목 목록을
  커밋하면 관심 종목이 인터넷에 그대로 노출된다. 시크릿은 아니므로 Secrets가 아니라
  Variables를 쓴다(로그에 찍혀도 무해하고, 마스킹 대상이 아니다).
- **하루 두 번, 시장별 분리 발송** — 미국장은 KST 새벽 05~06시, 한국장은 15:30에 마감한다.
  한 번만 보내면 한쪽은 항상 하루 늦은 데이터가 된다.
- **상태 파일 없음** — 직전 종가는 API가 응답에 담아 주므로 실행 간에 남길 상태가 없다.
  따라서 워크플로에 `contents: write` 권한도, 커밋 단계도, `concurrency` 그룹도 필요 없다.
- **LLM 실패는 발송을 막지 않는다** — 기존 파이프라인은 LLM 실패 시 exit 1이지만, 거기서는
  요약이 산출물의 본체다. 여기서는 시세가 본체이고 해설은 부가이므로 정책이 다르다.
- **급등락 기준 ±5%** — 대형주 기준으로 하루 하나도 안 나올 때와 여러 건 나올 때가 모두 있는
  선이다. `STOCKS_MOVE_THRESHOLD` 로 조정 가능하게 둔다.
- **공용 모듈 추출(`tghtml.py`, `gemini.py`)** — 텔레그램 HTML 이스케이프 규칙은
  `BUSINESS_RULES.md` 가 정본인데 구현이 둘로 갈리면 한쪽만 고쳐진다. Gemini 호출은
  ADR-005가 "모델 교체 시 손댈 파일은 `llm.py` 하나"라고 약속했으므로, 복제하면 그 약속이
  깨진다. 복제를 피하려면 추출이 필요하다.
