# 비즈니스 규칙

> 작성 기준: 코드가 구현해야 할 도메인 규칙의 정본. 규칙만 읽고 테스트 케이스를 도출할 수 있어야 한다. "적절히 처리한다" 금지 — 모든 엣지에 구체적 처리를 적는다. 구현(어느 함수가 처리하는지)은 쓰지 않는다. "가능한 것"과 짝지어 "불가능한 것"도 적는다.

## 용어

- {같은 단어가 문맥마다 다른 뜻이면 구분해서 정의. 예: "주문" = 결제 완료된 것만. 결제 전은 "장바구니"}

## 엔티티와 불변 조건

- {예: 주문(Order)은 항상 정확히 1명의 사용자에 속한다. 사용자 없는 주문은 존재할 수 없다}
- {예: 재고 수량은 음수가 될 수 없다}

## 상태 전이

{가능한 전이와 불가능한 전이를 모두.
예: 주문 pending → paid → shipped → delivered. paid → pending 역전이 불가. 취소는 shipped 이전에만 가능하며 cancelled는 종결 상태}

## 계산 로직

{입력 → 처리 → 출력을 명확한 식으로.
예: 최종 금액 = 상품 합계 − 쿠폰 할인(상품 합계의 최대 30%) + 배송비(상품 합계 5만 원 이상이면 0원)}

## 엣지 케이스

- {예: 재고 0인 상품이 장바구니에 있는 채 결제 시도 → 해당 상품을 제외할지 묻고, 동의 시에만 나머지로 진행}
- {예: 동일 쿠폰 중복 적용 시도 → 두 번째 적용을 거부하고 에러 코드 COUPON_ALREADY_APPLIED 반환}
