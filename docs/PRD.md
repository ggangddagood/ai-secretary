# PRD: ai-secretary

> 작성 기준: 무엇을 왜 만드는지의 정본. 구현 방법은 쓰지 않는다. "MVP 제외 사항"이 실질적인 범위 통제 장치다 — 여기 적힌 것은 요청 없이 만들지 않는다.

## 목표

AI 활용·수익화·마케팅 정보를 여러 소스에서 매일 수집해, 엄선 5건을 한국어 요약과 실행 힌트로
정리해 텔레그램으로 1회 보낸다. 정보를 찾으러 다니는 시간을 없애고, 읽을 것만 손에 쥐여 준다.

## 사용자

운영자 본인 1명. AI를 활용해 수익을 내려는 1인 개발자다. 다중 사용자, 가입, 인증 개념은 없다.

## 핵심 기능

1. **수집** — Hacker News(Algolia), GeekNews(RSS), GitHub Search, 지정 RSS 피드에서 지난 24시간
   (GitHub는 7일) 항목을 모은다.
2. **중복 제거** — 이미 발송한 항목(URL 정규화 후 동일)은 후보에서 뺀다.
3. **선별** — LLM이 4개 축(`tech`/`money`/`enterprise`/`marketing`)을 기준으로 5건을 고른다.
4. **요약** — 선별된 항목의 원문 본문을 추출해, 본문을 근거로 3줄 한국어 요약 + 실행 힌트 1줄을
   만든다. 본문을 확보하지 못한 항목은 제목·출처·링크만 싣는다.
5. **발송** — 텔레그램 봇으로 보내고, 성공한 항목만 발송 기록에 남긴다.

## 성공 기준

- 매일 08:00 KST에 브리핑이 텔레그램에 도착한다. 실패한 날에도 실패 사실이 메시지로 도착한다
  (조용히 아무것도 오지 않는 날이 없다).
- 도착한 브리핑 5건 중 최소 1건은 링크를 열어 읽을 만하다.
- 같은 항목이 두 번 오지 않는다.
- 요약 3줄이 원문에 없는 사실을 담지 않는다.

## MVP 제외 사항

- 카카오톡 발송 (텔레그램만)
- Threads / X(트위터) / Reddit 수집
- 웹 UI, 대시보드, 설정 화면
- 데이터베이스 (상태는 리포지토리 내 JSON 파일)
- 다중 사용자, 회원가입, 인증
- 발송 이력 검색·재발송 명령
- 사용자 피드백 학습(좋아요 기반 개인화)
- 요약 품질 자동 평가

## 디자인 방향

UI가 없다. 사용자가 보는 유일한 표면은 텔레그램 메시지이며, 포맷 규칙은
`src/secretary/render.py`와 `BUSINESS_RULES.md`가 정한다.
