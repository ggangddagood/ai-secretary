현재 브랜치의 변경 사항을 리뷰한다.

먼저 읽는다: `AGENTS.md`, `docs/STANDARDS.md`, `docs/ARCHITECTURE.md`, 그리고 해당 작업의 `phases/<task>/spec.md` (있으면).

`git diff`(base 브랜치 대비)로 변경 파일을 확인한 뒤 체크리스트로 검증한다. **주장이 아니라 증거** — 확인 명령을 실제로 실행하고 결과를 근거로 적는다.

## 체크리스트

1. **spec 준수** — spec의 요구 동작이 전부 구현되었는가. spec에 없는 기능이 추가되지 않았는가 ("범위 제외" 위반 포함)
2. **하드 게이트** — AGENTS.md의 CRITICAL 규칙 위반이 없는가
3. **아키텍처** — ARCHITECTURE.md의 구조를 따르는가. STANDARDS.md의 모듈 경계를 지키는가
4. **테스트** — 새 동작에 테스트가 존재하는가. spec의 엣지 케이스가 커버되는가
5. **검증** — `bash scripts/verify.sh`가 exit 0인가 (직접 실행해서 확인)
6. **외과성** — 요청과 무관한 변경(리팩터링, 포맷, 주석 정리)이 섞이지 않았는가
7. **문서** — 이번 변경으로 stale해진 docs/ 문장이 없는가. STATUS.md가 갱신되었는가

## 출력 형식

| 항목 | 결과 | 근거 |
|------|------|------|
| spec 준수 | ✅/❌ | {실행한 명령/확인한 파일과 결과} |
| 하드 게이트 | ✅/❌ | |
| 아키텍처 | ✅/❌ | |
| 테스트 | ✅/❌ | |
| 검증 | ✅/❌ | {exit code} |
| 외과성 | ✅/❌ | |
| 문서 | ✅/❌ | |

위반이 있으면 구체적 수정 방안을 제시한다. **리뷰만 하고, 수정은 사용자가 지시할 때만 한다.**
