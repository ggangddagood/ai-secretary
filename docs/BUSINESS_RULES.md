# 비즈니스 규칙

> 작성 기준: 코드가 구현해야 할 도메인 규칙의 정본. 규칙만 읽고 테스트 케이스를 도출할 수 있어야 한다. "적절히 처리한다" 금지 — 모든 엣지에 구체적 처리를 적는다. 구현(어느 함수가 처리하는지)은 쓰지 않는다. "가능한 것"과 짝지어 "불가능한 것"도 적는다.

## 용어

- **항목(Item)**: 소스에서 수집한 하나의 글/저장소. 제목·URL·출처·점수·발행 시각·짧은 설명을 갖는다.
- **후보**: 수집된 항목 중 발송 기록에 없는 것. 선별 대상이다.
- **본문(body)**: 원문 URL에서 추출한 기사 텍스트. 소스가 준 짧은 설명(`summary_hint`)은 본문이 아니다.
- **브리핑 항목(BriefEntry)**: 발송 메시지에 실리는 한 건. 요약이 있을 수도, 없을 수도 있다.
- **발송 기록(seen)**: 텔레그램 발송에 성공한 항목의 URL 키 → 발송 날짜 맵.

## 4개 축

선별과 표기에 쓰는 분류다. 모든 브리핑 항목은 정확히 하나의 축을 갖는다.

| 축 | 정의 |
| --- | --- |
| `tech` | AI 기술·도구·모델·프롬프트·에이전트 활용법 |
| `money` | AI로 수익을 낸 사례, 개인/소규모 팀의 제품 출시와 매출 공개 |
| `enterprise` | 기업이 실제 업무에 AI를 도입한 사례와 방법 |
| `marketing` | 개발자·1인 제품의 마케팅, 런칭, 그로스 전략 |

## 엔티티와 불변 조건

- 브리핑 항목은 항상 정확히 하나의 축에 속한다. 축이 없는 항목은 존재할 수 없다.
- 요약(`summary_ko`)이 있는 항목은 본문이 있었던 항목뿐이다. 본문 없이 만들어진 요약은 존재할 수 없다.
- 요약이 있으면 정확히 3줄이고, 각 줄은 완결된 한국어 문장이다.
- 요약이 없는 항목은 부제(`subtitle_ko`)와 실행 힌트(`action_hint_ko`)도 없다. 본문 없이 쓸 수 있는
  줄이 아니다.
- 발송 기록의 값은 `YYYY-MM-DD` 날짜 문자열이다. 다른 형식이 섞이면 그 파일 전체를 신뢰하지 않는다.
- 원문 제목은 원어를 유지한다. 번역하지 않는다 — 원문 검색 가능성을 잃는다.

## 선별 규칙

- 선별은 제목·출처·소스가 준 짧은 설명만 보고 한다. 이 시점에는 본문이 없다.
- 후보가 많으면 점수(score) 내림차순 상위 40건만 모델에 넘긴다. 점수가 없는 항목은 뒤로 간다.
- 목표 건수는 `BRIEF_ITEM_COUNT`(기본 5) 또는 `--limit N`이다.
- **가능하면 최소 3개 축을 포함**하되, 축을 채우려고 품질이 낮은 항목을 넣지 않는다. 우선순위는
  축 다양성이 아니라 유용성이다.
- 단순 뉴스 헤드라인(자금 조달, 인사, 주가)보다 독자가 따라 할 수 있는 내용을 앞에 둔다.
- 모델이 후보 목록에 없는 URL을 돌려주면 그 항목은 폐기한다. 만들어진 URL을 발송하지 않는다.
- 목표 건수보다 많이 돌려주면 앞에서부터 목표 건수까지만 쓴다.

## 중복 판정 규칙

같은 글인지 여부는 URL을 정규화한 뒤 비교한다. 정규화는 다음을 제거·통일한다.

| 요소 | 처리 |
| --- | --- |
| 스킴 | 항상 `https`로 통일 |
| 호스트 | 소문자화 후 선행 `www.` 제거 |
| 경로 | 말미 `/` 제거 |
| 쿼리 | `utm_*` 접두 파라미터와 `ref`/`fbclid`/`gclid` 제거, 남은 파라미터는 정렬 |
| 프래그먼트(`#...`) | 제거 |

- 호스트를 읽을 수 없는 값은 정규화하지 않고 원문 그대로 키를 만든다.
- 저장 키는 정규화된 URL의 sha1이다. 기록 파일이 원문 URL 목록으로 읽히지 않게 한다.
- 같은 실행 안에서는 정규화 이전의 URL 문자열이 같은 항목만 중복으로 본다(수집 단계 중복 제거).
  발송 기록과의 대조는 위 정규화를 거친 키로 한다.

## 발송 기록 규칙

- 기록은 **텔레그램 발송이 성공한 뒤에만** 갱신한다. 발송 실패 시 기록이 없어야 다음 실행에서
  같은 항목이 다시 후보가 된다.
- `--dry-run`은 기록을 갱신하지 않는다.
- 보존 기간은 **90일**이다. 저장 시점에 그보다 오래된 항목을 지운다. 90일이 지난 글이 다시
  후보로 잡히는 것은 허용한다 — 실제로 다시 화제가 된 글이라면 볼 가치가 있다.
- 기록 파일이 없거나 깨졌거나 버전이 다르면 경고 로그를 남기고 빈 기록으로 시작한다. 실행은 계속한다.
  (그날 이미 본 항목이 다시 올 수 있지만, 조용히 아무것도 안 보내는 것보다 낫다.)

## 요약 규칙

- 요약의 유일한 근거는 추출된 본문이다. 제목·소스 설명·모델의 배경 지식으로 빈 곳을 채우지 않는다.
- 추출된 본문이 300자 미만이면 추출 실패로 본다. 짧은 조각으로 요약하면 나머지를 지어낸다.
- 본문은 8000자까지만 쓴다.
- 본문이 없는 항목은 아예 모델에 보내지 않는다.
- 모델이 본문을 보냈는데도 요약을 빠뜨린 항목은 요약 없이 싣는다(경고 로그).

## 렌더링 규칙

- 텔레그램 `parse_mode=HTML`. `&`, `<`, `>`만 이스케이프하고, 링크 속성값은 `"`까지 막는다.
- 메시지 한 건은 4096자를 넘지 않는다. 넘으면 **항목 경계**에서 나눠 순서대로 보낸다.
- 항목 하나가 단독으로 4096자를 넘으면 줄 경계에서 자르고 말줄임표를 붙인다. 태그 중간에서 자르면
  텔레그램이 HTML 파싱에 실패한다.
- 헤더 날짜는 KST 기준이다. UTC로 찍으면 08:00 KST 발송분이 하루 전 날짜로 나온다.

## 엣지 케이스

| 상황 | 처리 |
| --- | --- |
| 소스 1개가 타임아웃/HTTP 에러 | 경고 로그 후 그 소스만 건너뛴다. 나머지로 진행 |
| 모든 소스 실패 또는 후보 0건 | 실패 알림 메시지를 발송하고 exit 1 |
| 중복 제거 후 후보가 5건 미만 | 있는 만큼만 담는다. 부족을 이유로 실패시키지 않는다 |
| 한 건도 선별되지 않음 | 빈 브리핑을 보내지 않는다. 실패 알림 후 exit 1 |
| 본문 추출 실패(paywall, JS 렌더링, 404, HTML 아님) | 그 항목은 제목·축·출처·링크만. 나머지는 정상 처리 |
| LLM 호출 실패 | 실패 알림 발송 후 exit 1 |
| 텔레그램 발송이 중간 조각에서 실패 | 전체를 실패로 본다. 발송 기록을 갱신하지 않고 exit 1 |
| HTTP 200인데 응답이 `ok: false` | 발송 실패로 본다 |
| 실패 알림 발송마저 실패 | 로그만 남긴다. 재시도할 채널이 없다 |
| 같은 날 두 번 실행 | 1회차 항목은 기록에 있으므로 2회차는 다른 항목이 선별된다. 중복 발송 없음 |

## 주가 브리핑 규칙

여기서부터는 `secretary.stocks` 파이프라인의 규칙이다. 위 규칙과 공유하는 것은 텔레그램 HTML
이스케이프·4096자 분할뿐이고, 선별·중복 판정·요약 규칙은 적용되지 않는다.

### 용어

- **관심 종목(Ticker)**: 사용자가 환경 변수로 주입한 감시 대상. `심볼:표시명` 쌍이다.
  표시명은 화면 표기이자 뉴스 검색어다.
- **시장 지표**: 시장마다 고정된 지수·환율. 코드 상수이며 사용자가 바꾸지 않는다.

  | 시장 | 지표 |
  | --- | --- |
  | `us` | `^GSPC`(S&P 500), `^IXIC`(나스닥), `USDKRW=X`(원달러) |
  | `kr` | `^KS11`(코스피), `^KQ11`(코스닥), `USDKRW=X`(원달러) |

- **급등락 종목**: 등락률의 절댓값이 임계값 이상인 **관심 종목**. 시장 지표는 대상이 아니다.
- **기준일(as_of)**: 최신 유효 종가가 속한 거래일. 거래소 타임존 기준 날짜다.
- **헤드라인(Headline)**: 급등락 종목의 근거로 모은 뉴스의 제목·링크·발행 시각. 본문이 아니다.
- **해설(comment_ko)**: 급등락 종목이 왜 움직였는지에 대한 한국어 한 줄. 헤드라인이 유일한 근거다.

### 관심 종목 목록 형식

`STOCKS_WATCHLIST_US` / `STOCKS_WATCHLIST_KR` 는 쉼표로 구분된 `심볼:표시명` 목록이다.

- 표시명을 생략하면(`AAPL`) 심볼을 표시명으로 쓴다.
- 앞뒤 공백은 제거한다. 빈 항목은 건너뛴다.
- 표시명에 콜론이 들어갈 수 있으므로 **첫 콜론에서만** 나눈다.
- 심볼이 없는 항목은 그 항목만 건너뛴다(경고 로그). 목록 전체를 버리지 않는다.
- 목록이 비어 있어도 실패가 아니다. 시장 지표만으로 브리핑을 만든다.

### 등락률 계산 규칙

- 조회는 시장 지표와 관심 종목 각각에 대해 심볼 하나당 한 번이다.
- 등락률은 `indicators.quote[0].close` 배열에서 `None`을 제거한 **유효값의 마지막 두 개**로
  계산한다: `(최신 - 직전) / 직전 * 100`.
- **`meta.chartPreviousClose`로 계산하지 않는다.** 이 값은 조회 창 시작 *이전*의 종가이지
  직전 거래일 종가가 아니다. 쓰면 등락률이 예외 없이, 그럴듯한 숫자로 틀린다.
- 유효값이 2개 미만이면 그 심볼은 조회 실패다. 등락률을 만들 수 없다.
- 직전 종가가 `0`이면 조회 실패다. 0으로 나누지 않는다.
- 기준일은 최신 유효 종가에 대응하는 `timestamp`를 `meta.exchangeTimezoneName` 타임존으로
  변환한 날짜다.

### 급등락 판정 규칙

- `abs(등락률) >= STOCKS_MOVE_THRESHOLD`(기본 `5.0`)인 관심 종목이 급등락 종목이다.
- 시장 지표는 판정 대상이 아니다 — 지수와 환율은 해설하지 않는다.
- 급등락 종목이 0건이면 해설 절을 통째로 생략한다. 시세만 발송한다.

### 해설 규칙

- **해설의 유일한 근거는 헤드라인이다. 헤드라인을 확보하지 못한 종목에 해설을 생성하지 않는다.**
  AI 브리핑의 "본문 없으면 요약 없음"과 같은 규칙이다 — 근거 없는 해설은 환각이다.
- 헤드라인은 종목의 **표시명**을 검색어로 Google News RSS에서 모은다. 언어 파라미터는 시장을
  따른다(`us` → `hl=en-US&gl=US&ceid=US:en`, `kr` → `hl=ko&gl=KR&ceid=KR:ko`).
- 발행 시각이 **최근 3일 이내**인 헤드라인만, 종목당 최대 5건까지 쓴다.
- 뉴스 **본문은 추출하지 않는다**. 제목·링크·발행 시각까지다.
- 헤드라인을 확보한 종목들을 **한 번의 LLM 호출**로 묶는다. 해설은 종목당 한국어 한 줄이다.
- 매매 신호·목표가·투자 판단을 쓰지 않는다. 움직임의 배경만 적는다.
- 모델이 프롬프트에 없던 심볼의 해설을 돌려주면 폐기한다.
- 발송 메시지에는 해설과 함께 근거 헤드라인의 제목·링크를 싣는다.

### 휴장 판정 규칙

- 기준일이 실행 시각의 그 시장 로컬 날짜와 다르면 **휴장**으로 보고 헤더에 표시한다.
- 환율(`USDKRW=X`)은 24시간 거래이므로 판정에서 제외한다. 최신값을 그대로 싣는다.
- 환율을 뺀 조회 결과가 하나도 없으면 기준일을 알 수 없다. 날짜를 지어내지 않고 비워 둔다.
- 휴장이어도 마지막 거래일 종가를 그대로 싣는다. 발송을 거르지 않는다.

### 렌더링 규칙

- 텔레그램 `parse_mode=HTML`. 이스케이프와 4096자 상한은 위 "렌더링 규칙"과 같다. 넘치면
  **블록 경계**(지수 / 관심 종목 / 급등락)에서 나눈다.
- 헤더에 시장 이름(`미국장` / `한국장`)과 KST 기준 발송 날짜, 기준일을 표시한다. 휴장이면
  기준일 옆에 함께 표시한다.
- 숫자 포맷: 지수·환율은 소수 2자리, 통화가 `KRW`인 종목은 정수, 나머지는 소수 2자리.
  원 단위로 거래되는 한국 주식에 소수점을 붙이면 없는 정밀도가 생긴다.
- 등락률은 부호와 방향을 함께 쓴다: 상승 `▲`, 하락 `▼`, 보합 `–`.
- 빈 절은 블록 자체를 생략한다. 제목만 남은 절을 보내지 않는다.

### 주가 브리핑 엣지 케이스

| 상황 | 처리 |
| --- | --- |
| `close` 배열 마지막 원소가 `None` | 제거하고 그 앞의 유효값을 최신 종가로 쓴다 |
| `close` 유효값이 2개 미만 | 그 심볼은 조회 실패로 본다. 등락률을 만들 수 없다 |
| 직전 종가가 `0` | 조회 실패로 본다. 0으로 나누지 않는다 |
| 심볼 하나가 타임아웃·HTTP 에러·`chart.error` | 경고 로그 후 그 심볼만 건너뛴다. 나머지로 진행 |
| 관심 종목·시장 지표 조회가 **전부** 실패 | 실패 알림을 발송하고 exit 1 |
| 관심 종목 목록이 비어 있음 | 경고 로그 후 시장 지표만으로 브리핑을 만든다. 실패가 아니다 |
| 관심 종목 목록 항목의 형식이 잘못됨(빈 문자열 등) | 그 항목만 건너뛴다. 경고 로그 |
| 기준일이 그 시장 로컬 날짜와 다름(공휴일) | 마지막 거래일 종가를 그대로 싣고 헤더에 "휴장"을 표시한다 |
| 환율(`USDKRW=X`)의 기준일 | 24시간 거래라 휴장 판정에서 제외한다. 최신값을 그대로 싣는다 |
| 급등락 종목이 0건 | 해설 절을 통째로 생략한다. 시세만 발송한다 |
| 뉴스 RSS 수집 실패 | 경고 로그 후 그 종목은 해설 없이 간다. 전체를 실패시키지 않는다 |
| 최근 3일 내 헤드라인이 0건 | 그 종목은 해설 없이 등락률만 |
| LLM 호출 실패 | **경고 로그 후 해설 없이 발송한다.** 시세가 본체이고 해설은 부가다 |
| LLM 응답에 일부 종목이 빠짐 | 빠진 종목만 해설 없이 싣는다. 경고 로그 |
| LLM이 헤드라인 없는 종목의 해설을 반환 | 그 해설을 폐기한다. 근거 없는 해설은 싣지 않는다 |
| 텔레그램 발송이 중간 조각에서 실패 | exit 1. 실패 알림도 보내지 않는다(같은 채널이 죽었다) |
| Yahoo가 429로 차단 | 조회 실패 경로를 탄다 — 전부 실패면 실패 알림 + exit 1. 조용히 끝나지 않는다 |
