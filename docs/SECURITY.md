# 보안

> 작성 기준: 무엇을 보호하고, 누가 무엇을 할 수 있고, 무엇을 기록하는지. 성공 경로만이 아니라 실패 경로(잘못된 크리덴셜, 만료, 잠금)를 적는다. "보안 베스트 프랙티스를 따른다" 같은 문장 금지 — 이 프로젝트의 결정만. 해당 없는 항목은 지우고, 보안 표면이 전혀 없는 프로젝트면 이 파일을 삭제한다.

## 인증 흐름

{진입부터 인증 완료까지의 단계 + 각 단계의 실패 처리.
예: 이메일+비밀번호 → 실패 5회 시 15분 잠금. 세션은 httpOnly 쿠키. 만료 시 401 → 클라이언트는 로그인으로 리다이렉트}

## 인가 모델

{주체 · 행위 · 조건의 매트릭스. 명시적으로 금지된 것도 적는다.
예: user는 자신의 주문만 조회/취소. admin은 모든 주문 조회 가능하나 결제 수단 원문은 누구도 조회 불가}

## 민감 데이터

{무엇이 민감하고 어떻게 다루는지 — 저장/로깅/마스킹.
예: 비밀번호는 argon2 해시만 저장. 로그에 이메일 전체 출력 금지(앞 2자 + 마스킹)}

## 크리덴셜

{수명 · 저장 위치 · 로테이션.
예: 세션 토큰 7일, httpOnly + Secure 쿠키. 외부 API 키는 환경 변수로만 — 코드/로그에 등장 금지}

## 감사 로그

{기록해야 할 이벤트의 구체적 목록.
예: 로그인 성공/실패, 권한 변경, 주문 취소, 관리자의 사용자 데이터 조회}
