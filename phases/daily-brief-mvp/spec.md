# Spec: daily-brief-mvp

## 목표

AI 활용·수익화·마케팅 정보를 여러 소스에서 매일 수집해, 엄선 5건을 한국어 요약과 실행 힌트로 정리해 텔레그램으로 1회 발송한다.

## 사용자

이 서비스의 사용자는 운영자 본인 1명이다. 다중 사용자, 가입, 인증 개념은 없다.

## 요구 동작

- 매일 정해진 시각(기본 08:00 KST)에 배치가 1회 실행되면, 아래 소스에서 지난 24시간(GitHub는 7일) 항목을 수집한다:
  - Hacker News (Algolia Search API — front page + AI 키워드 검색)
  - GeekNews (RSS)
  - GitHub Search API (최근 생성·급상승 AI 관련 저장소)
  - 지정된 RSS 피드 목록 (AI 회사 블로그, 인디해커·마케팅 뉴스레터)
- 수집된 항목 중 이미 발송한 항목(URL 정규화 후 동일)은 후보에서 제외한다.
- 남은 후보를 LLM에 넘겨 5건을 선별한다. 선별 기준은 아래 4개 축이다:
  1. `tech` — AI 기술·도구·모델·프롬프트·에이전트 활용법
  2. `money` — AI로 수익을 낸 사례, 개인/소규모 팀의 제품 출시와 매출 공개
  3. `enterprise` — 기업이 실제 업무에 AI를 도입한 사례와 방법
  4. `marketing` — 개발자·1인 제품의 마케팅, 런칭, 그로스 전략
- 선별된 5건 각각에 대해 원문 본문을 추출한다.
- 본문 추출에 성공한 항목은 3줄 한국어 요약 + "실행 힌트" 1줄을 생성한다.
- 본문 추출에 실패한 항목은 요약과 실행 힌트 없이 제목·출처·링크만 표기한다.
- 완성된 브리핑을 텔레그램 봇으로 발송한다. 발송에 성공한 항목의 URL은 발송 기록에 저장되어 다음 실행에서 후보로 잡히지 않는다.
- `--dry-run` 으로 실행하면 텔레그램 발송과 발송 기록 저장을 하지 않고 브리핑 본문을 stdout에 출력한다.
- 수집 결과가 0건이거나 모든 소스가 실패하면, 브리핑 대신 실패 사실을 알리는 메시지를 텔레그램으로 발송하고 프로세스는 실패(exit≠0)로 끝난다.

## 불변 조건

- 본문을 확보하지 못한 항목에 대해 요약을 생성하지 않는다. 제목만 보고 내용을 추측한 요약은 금지한다.
- 소스 하나가 실패해도 나머지 소스의 결과로 브리핑을 만든다. 개별 소스 실패가 전체 실행을 중단시키지 않는다.
- 발송 기록(`state/seen.json`)은 텔레그램 발송이 **성공한 뒤에만** 갱신한다. 발송 실패 시 기록을 남기지 않아 다음 실행에서 재시도 가능해야 한다.
- 시크릿(봇 토큰, API 키)은 환경 변수로만 주입한다. 코드·로그·발송 메시지·커밋에 노출하지 않는다.
- 모든 환경 변수는 `config.py`에서 검증 후 사용한다. 다른 모듈에서 `os.environ` 직접 참조 금지.
- 실패했든 성공했든 실행 결과는 항상 사용자에게 도달한다. 조용히 아무것도 보내지 않고 끝나는 경로를 만들지 않는다.

## 범위 제외

이번에 만들지 않는다. 실행자는 요청 없이 아래를 구현하지 않는다.

- 카카오톡 발송 (텔레그램만)
- Threads / X(트위터) / Reddit 수집
- 웹 UI, 대시보드, 설정 화면
- 데이터베이스 (상태는 리포지토리 내 JSON 파일)
- 다중 사용자, 회원가입, 인증
- 발송 이력 검색·재발송 명령
- 사용자 피드백 학습(좋아요 기반 개인화)
- 요약 품질 자동 평가

## 엣지 케이스

| 상황 | 처리 |
| --- | --- |
| 소스 1개가 타임아웃/HTTP 에러 | 경고 로그 남기고 그 소스만 건너뜀. 나머지로 진행 |
| 모든 소스 실패 또는 후보 0건 | "오늘 수집 실패: {사유}" 텔레그램 발송 후 exit 1 |
| 중복 제거 후 후보가 5건 미만 | 있는 만큼만 브리핑에 담는다. 부족을 이유로 실패시키지 않음 |
| 본문 추출 실패(paywall, JS 렌더링, 404) | 해당 항목은 요약 없이 제목·출처·링크만. 나머지 항목은 정상 처리 |
| LLM 호출이 재시도 후에도 실패 | "오늘 브리핑 생성 실패: {사유}" 텔레그램 발송 후 exit 1 |
| 렌더링된 메시지가 텔레그램 4096자 초과 | 항목 경계에서 분할해 여러 건으로 순차 발송 |
| 텔레그램 발송 실패 | exit 1. 발송 기록 갱신하지 않음 |
| 같은 날 두 번 실행 | 1회차에 보낸 항목은 발송 기록에 있으므로 2회차에는 다른 항목이 선별됨. 중복 발송 없음 |
| 발송 기록 파일이 없거나 깨짐 | 빈 기록으로 시작하고 경고 로그. 실행은 계속 |

## 외부 인터페이스

### CLI

```
python -m secretary.main [--dry-run] [--limit N]
```

- `--dry-run`: 텔레그램 발송 및 발송 기록 저장 없이 stdout 출력
- `--limit N`: 브리핑 항목 수 (기본 5)
- exit 0 = 발송 성공(또는 dry-run 성공), exit 1 = 실패

### 소비하는 외부 API

| 대상 | 엔드포인트 | 인증 |
| --- | --- | --- |
| Hacker News | `https://hn.algolia.com/api/v1/search` | 없음 |
| GeekNews | `https://news.hada.io/rss/news` | 없음 |
| GitHub | `https://api.github.com/search/repositories` | 없음(60req/h) 또는 `GITHUB_TOKEN` |
| RSS 피드 | 각 피드 URL | 없음 |
| Gemini API | `google-genai` SDK | `GEMINI_API_KEY` |
| Telegram | `https://api.telegram.org/bot<token>/sendMessage` | `TELEGRAM_BOT_TOKEN` |

### 환경 변수

| 이름 | 필수 | 기본값 | 용도 |
| --- | --- | --- | --- |
| `TELEGRAM_BOT_TOKEN` | O | — | 봇 인증 |
| `TELEGRAM_CHAT_ID` | O | — | 수신 채팅 ID |
| `GEMINI_API_KEY` | O | — | Gemini API |
| `GITHUB_TOKEN` | X | 없음 | GitHub API rate limit 완화 |
| `BRIEF_ITEM_COUNT` | X | `5` | 브리핑 항목 수 |
| `STATE_PATH` | X | `state/seen.json` | 발송 기록 경로 |
| `HTTP_TIMEOUT` | X | `20` | 외부 HTTP 타임아웃(초) |

## 확정 근거

### 사용자 답변으로 확정

- **전달 채널 = 텔레그램 봇**. 카카오톡 "나에게 보내기"는 기본 텍스트 템플릿 200자 제한 + access token 6시간/refresh token 약 2개월 재인증이 필요해 무인 배치가 조용히 끊긴다. 텔레그램은 봇 토큰 하나, 만료 없음, 4096자, HTML 포맷 지원.
- **스택 = Python + GitHub Actions**. 서버 비용 0, cron·Secrets·실패 알림 내장. 웹 화면이 없는 순수 배치이므로 서버리스 호스팅이 불필요.
- **수집 소스 = 무인증 소스만**. Threads 키워드 검색은 Meta App Review + 비즈니스 인증이 필요하고, Reddit은 신규 OAuth 앱 수동 승인 대기가 보고된다. Hacker News(Algolia)·GeekNews·GitHub·RSS는 승인 없이 즉시 동작한다.
- **브리핑 구성 = 엄선 5건 + 3줄 요약 + 실행 힌트 1줄**, 4개 축에서 선별.

### 스스로 확정 (근거 포함)

- **LLM = Gemini `gemini-3.6-flash` (`google-genai` SDK)**. 사용자가 유료 API 결제 없이 시작하기로 결정했다. Google AI Studio 무료 티어는 신용카드 없이 키를 발급하고, 하루 요청 한도가 수백 건이라 하루 2회 호출인 이 배치에는 충분하다. 대가로 두 가지를 감수한다: (1) 무료 티어는 입력·출력이 Google의 제품 개선에 사용될 수 있다 — 이 배치가 보내는 것은 공개된 기사 본문과 제목뿐이므로 비공개 정보 유출 위험은 없다. (2) 무료 티어 한도·정책은 예고 없이 바뀔 수 있다. 유료 전환이 필요해지면 교체 지점은 `llm.py` 한 파일이다.
- **2단계 LLM 호출(선별 → 본문 추출 → 요약)**. 1회 호출로 선별과 요약을 동시에 하면 제목만 보고 요약을 지어내는 환각이 발생한다. 요약은 반드시 추출된 본문을 근거로 한다.
- **구조화 출력은 Gemini `response_format`(JSON Schema) + Pydantic 스키마**. 자유 텍스트 파싱·재시도 루프를 없앤다.
- **상태 저장 = 리포지토리 내 `state/seen.json`을 GitHub Actions가 커밋**. DB 불필요, 무료, 히스토리로 "지난주에 뭘 받았는지" 조회 가능. GitHub Actions Cache는 7일 만료라 부적합.
- **발송 시각 = 08:00 KST (cron `0 23 * * *` UTC)**. 환경 변수가 아닌 워크플로 cron으로 조절하며, 변경이 결과 의미를 바꾸지 않으므로 실행 단계 재량이 아닌 고정값으로 둔다.
- **텔레그램 `parse_mode=HTML`**. MarkdownV2는 `.`, `-`, `(` 등 이스케이프 규칙이 까다로워 요약 문장에서 발송 실패를 유발한다. HTML은 `&`, `<`, `>` 3개만 이스케이프하면 된다.
- **본문 추출 = `trafilatura`**. 광고·네비게이션 제거 품질이 좋고 순수 파이썬으로 설치가 단순하다.
- **요약 언어 = 한국어. 원문 제목은 원어 유지**하고 한국어 한 줄 부제를 덧붙인다. 원문 검색 가능성을 유지하기 위함이다.

## 필수 검증

- `bash scripts/verify.sh` (ruff + pytest)
- `python -m secretary.main --dry-run` 이 실제 소스를 수집해 브리핑을 stdout에 출력하고 exit 0
- GitHub Actions에서 `workflow_dispatch` 수동 실행 시 텔레그램으로 브리핑 1건 도착
